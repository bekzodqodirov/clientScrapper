| Rule | Detail |
|---|---|
| Markers | `live` (network, VPS only), `slow` (CS_RUN_SLOW=1), default = pure or Postgres. `pytest -q` on a laptop without Postgres **skips** DB tests; CI sets `CS_REQUIRE_DB=1` and a skip becomes a failure (MIYA `conftest.py` pattern; a suite that silently ran without its database cannot pass). |
| DB fixture | `session` yields an `AsyncSession` after `TRUNCATE <all tables except sources, scoring_weights> RESTART IDENTITY CASCADE` in **one statement**. `TRUNCATE` is used on purpose: the `cs_append_only` triggers refuse row `DELETE` on `push_log`, `outcomes`, `merge_log`, `purge_log`, `usage_log`, and `TRUNCATE` does not fire row triggers. `sources` and `scoring_weights` are migration-seeded configuration: a test that flips `sources.enabled/config` or activates a weights version snapshots in `beforeAll`-style fixture setup and restores it (fullprompt #716 — a restore written after the fact restores what it found). |
| Time | Every function under test takes `now:` explicitly; tests pass fixed Tashkent-aware datetimes. Anything compared against the real clock derives from the real clock. `CS_TIME_TRAVEL=newyear|+400d` (port of MIYA `tests/timetravel.py`) runs the non-DB suite at another moment in CI (§2.1) — the Tashkent-day, push-window and decay maths must not depend on the calendar of the day the test was written. |
| Synthetic data | Visibly fake: companies «Namuna …», phones `+998 90 000 00 NN` — and, where the normaliser must be tested on other codes, the same shape under any operator or area code (`+998 XX 000 00 NN`, the landline shape `+998 XX 200 00 NN`) and placeholders whose seven subscriber digits are one digit repeated; `scripts/secret_scan.py`'s `synthetic()` accepts exactly these, plus the three numbers the spec and the docs print (`SPEC_EXAMPLE_TAILS`: 04 §1.1's `+998 90 123 45 67`, the statistics register office's line in `docs/manbalar.json`, the PD-register hotline in `docs/huquqiy-memo.md`) — STIR `3000000NN`, handles `namuna_<n>`, e-mails `namuna_NN@example.uz`, domains `*.example.uz`. No ERP export, no real person, no real phone ever enters `tests/` or `docs/`. `tests/test_forbidden_strings.py` (new) greps the tree for the strings in the CI secret `CS_FORBIDDEN_STRINGS` (real names, handles, phone tails the owner lists; empty until set) — the MIYA username guard, generalised. |
| Red proof | A test for a fix is shown to fail without the fix by a string edit of the code, then undone by string edit — never `git stash`/`git checkout` (fullprompt #430). Commit before a series of red proofs. |
| Assertion shape | A parser test asserts concrete field values, never `len(result) > 0` alone; a parser that returns `[]` on its own fixture fails. A test that restates the code (re-implements the formula) proves nothing — call the real function with inputs and pin outputs. |

### 1.1 Pure parser tests with fixtures

Every collector is `parse_<page>(body: bytes, *, url, fetched_at) -> list[Observation]` (03 §1.2) tested on recorded bytes; the fetch layer is tested once (`tests/collectors/test_http.py`).

**Capture tool** — `tools/record_fixture.py` (new):

```
python -m clientscrapper.tools.record_fixture <url> --key <source_key> --name <name>
       [--json] [--header k=v]... [--post-json file] [--scrub auto|on|off] [--note "..."]
       [--root tests/fixtures] [--paid <operation> --est <usd>]
```

Goes through `Fetcher` (UA, robots, rate limits apply; at a documented JSON API — `http.ROBOTS_OPTOUT_HOSTS` — robots.txt is skipped as the collector that calls it skips it, so the fixture is the answer the collector gets). A metered host (`http.METERED_HOSTS`: Brave, Yandex search, Places, 2GIS, Apify) is refused unless `--paid <operation> --est <usd>` names the call; then it goes through `costs.ask` like any paid call — a `usage_log` row with `source_key=<key>`, refused at a cap before anything is sent, the estimate being both the claim and the price. Writes `tests/fixtures/<key>/<name>.<html|json|xml>` and `<name>.headers.json` (status, final URL, the response headers with `Set-Cookie`, `Authorization` and every key header stripped, every URL through `scrub_url`), and adds (or replaces) its README line. `--scrub auto` (default) applies `tools/scrub_fixture.py` (`needs_scrub`) to the person-tier sources — `scrub_fixture.PERSON_TIER_SOURCES` = `olx_business`, `instagram_discovery`, `telegram_monitor`, `hh_vacancies` (a vacancy's `contacts` block is the HR person: a name, an e-mail, phones) and `uzum_sellers` (a seller is often a YaTT) — to any page naming an individual entrepreneur (`IP|ИП|YaTT|ЯТТ` next to a person-shaped name), and to any page carrying a person-shaped name in a person field (`user`/`seller`/`owner`/`author`/`contact`/`contacts`/`contact_person`/`contactPerson`/`person`/`profile` → `name` at any depth, `user_name`, `sellerName`, `first_name` …): phones → deterministic synthetic `+998 90 000 00 NN` digit for digit (same real number → same NN inside one file; a foreign number keeps its country code; hh's split `country`/`city`/`number` phone is one number with the NN of its `formatted` twin), `@handles`, `t.me/<name>` and Instagram handles → `namuna_NN`, e-mails → `namuna_NN@example.uz` (one already at an `example.*` domain stays, unless its local part is a person's name), person names → `Seller NN`; the URL and the stored headers go through the same mapping, and a scrubbed page's `content-length` is dropped; structure, keys and lengths are kept so selectors still match. Company-tier public pages (directories, exhibitors, brand pages, registries) are stored verbatim; hh employer pages are recorded under `hh_vacancies`, a person-tier source as a whole, and so are scrubbed too (a firm's name is not person-shaped and stays). The README line says `scrubbed: yes|no`.

**Refresh policy.** A fixture is re-recorded when (a) its `@live` smoke test turns red (selector drift), (b) the quarterly `make smoke` run on the VPS (1st of Jan/Apr/Jul/Oct, cron, result posted to the owner digest as «Tekshiruv: N ta manba oʻzgardi») lists it, or (c) a parser change needs a new shape. A refresh is one commit containing the new fixture, the README line, and the parser change; the old file is kept only as `<name>.<yyyymmdd>.html` when the parser must support both shapes (then both are tested). Fixtures are never edited by hand except through the scrubber.

**Per collector** (`tests/collectors/test_<key>_parse.py`): each `parse_*` × each fixture → exact `company_name_raw`, `phones` (raw strings), `telegram`, `instagram`, `website`, `signal_types`, `excerpt` prefix, `external_ids`, `attrs` numbers; plus the negative fixture (a page of the same site that must yield `[]` — e.g. a 404 page, a CAPTCHA page, a non-UZ exhibitor row) and the paginator-stop case where it applies.
